  Scenario and playbooks

  The matcher offered two scenarios. Neither fits on its own, so I'm combining
  them:

    RelationshipAttestation:1 contract, so there's no custom contract to write.
    Tide's own test of this contract showed that data encrypted under one policy
    can be decrypted under another policy for the same record. That lets
    applicants write data that only the panel can read.
  - iga-admin-governance for the reveal. It makes the reveal a governed change
    that needs 2 of 3 approvals.

  Playbooks, in order: start-tidecloak-dev → bootstrap-realm-from-template →
  initialize-admin-and-link-account (once per panel member) →
  configure-e2ee-roles-and-policies → add-auth-nextjs-fresh (copied from

  Roles

  │                │                       │ identity.                      │
  └────────────────┴───────────────────────┴────────────────────────────────┘

  Quorum: the 3 panel members are the realm's only tide-realm-admins. Tide sets
  the approval threshold as max(1, floor(0.7 × admins)), which is exactly 2 for
  3 admins. Making the app admin a realm admin would make 4 admins, still with a
  threshold of 2. Admin plus one panel member could then reveal, so I'm keeping
  them out.

  Policies

  There are two RelationshipAttestation:1 policies, both with assignmentId = 
  identity-<cycleId>. Every identity field is tagged with that one id and
  nothing else.

  1. Write-only drop box: subject Role: applicant, roles ["_tide_encryptor"].
     Applicants can encrypt but never decrypt.
  2. Panel read: subject Role: selection-panel, roles ["_tide_decryptor"]. The
     panel signs it at setup. It does nothing yet.

  What keeps Stage 1 blind: nobody holds _tide_decryptor. Reviewers, admin and
  the server all fail the check on every Tide key server, and the server has no
  key at all.

  How the reveal works: one change request adds _tide_decryptor to the
  selection-panel composite role. It needs 2 of 3 panel approvals in the Tide
  enclave and commits on its own once the threshold is met. If composite-role
  changes turn out not to be governed this way, the fallback is to grant
  _tide_decryptor to each panel member, one change request each. Each still
  needs 2 approvals.

  Data model (SQLite, synthetic seed)

  - cycles: id, name, stage ('blind'|'reveal'), scores_locked_at, reveal_cr_id
  - criteria: id, cycle_id, label, max_score
  - applications: id, cycle_id, applicant_sub, work_samples (plaintext JSON), 
    identity_ct (ciphertext only: name, email, university, small photo).
    applicant_sub is never returned to reviewers.
  - scores: id, application_id, reviewer_sub, scores_json, comment, 
    submitted_at, locked
  - policies: assignment_id, purpose ('write'|'read'), signed_bytes. Only panel
    members can store these, and the server checks them before saving.

  Every API route checks the login token, the DPoP proof (which ties the token
  to the browser) and the role on the server, not just in the UI.

  Demo flow mapping

  1. Reviewer scores a portfolio anonymously: the /review page shows work
     samples only.
  2. Reviewer and admin click "Reveal identity" early: the browser tries to
     decrypt and Tide refuses ('_tide_decryptor' role not found). The page shows
     "Access denied by Tide network". Bonus: flip stage in the database by hand
     and decryption still fails.
  3. Admin presses "Advance": the server refuses because there's no committed
     change request, and admin can't approve one. Panel member A proposes the
     change (only allowed once all scores are locked), A and B approve in the
     enclave, and the stage advances.
  4. Panel member re-logs in: the new role takes effect (this can take up to
     about 2 minutes), then they decrypt and the identity shows.

  Limits to state in the pitch

  - The "all scores locked" precondition is checked by our server, not by Tide.
    Panel members could open the change request in the TideCloak console anyway,
    but they would still need 2 of 3. Having Tide enforce it would need a
    custom contract deployed by the Tide team, which is out of scope.
  - A reveal can't be undone for anyone who has already decrypted.
  - The plan assumes your local Tide network has the RelationshipAttestation:1 
    contract (networks updated since 2026-10-16). I'll confirm this when the
    first policy is signed.
  - Setup takes some time. Each of the 3 panel members must link a Tide account,
    and every demo user must sign in once.
